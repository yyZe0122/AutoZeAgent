# YunmengZe Agent v0.2.3

**Alpha · Pre-release**  
**Alpha · 预发布**

OpenCode-style **model selection / wire id**, nested catalog keys, optional `models.<key>.id`, and dual-supplier templates (`deepseek1` / `deepseek2`).

OpenCode 风格 **模型选择与上游 wire id**、可含 `/` 的 catalog key、可选 `models.<key>.id`，以及双供应商模板（`deepseek1` / `deepseek2`）。

## Highlights / 亮点

| Area | Change |
| --- | --- |
| **Selection** | Top-level `model` is `providerID/modelID…` — only the **first** `/` splits supplier from model segment (model segment may contain `/`). |
| **Wire id** | HTTP body `model` = `models.<key>.id` if set, else the model segment (OpenCode `api.id`). No bare-prefix strip of nested ids. |
| **Catalog** | Keys under `provider.<id>.models` match the model segment exactly (may contain `/`). Mistyped `providerID/modelID` keys still accepted as convenience. |
| **Templates** | Default / install seeds and README use **`deepseek1`** (official bare ids) + **`deepseek2`** (gateway nested ids / `id` override). Env: `DEEPSEEK1_API_KEY` / `DEEPSEEK2_API_KEY`. |
| **Resolved** | `SelectionRef` (full selection) vs `ModelID` (wire) — runtime / TUI / diagnostics use selection for display and switch; agent requests use wire. |
| **Docs** | `docs/provider-protocols.md`, `configs/agent.json.example`, README, install scripts aligned. |

### Config examples / 配置示例

```json
{
  "model": "deepseek1/deepseek-chat",
  "provider": {
    "deepseek1": {
      "type": "openai-compatible",
      "options": {
        "baseURL": "https://api.deepseek.com/v1",
        "apiKey": "{env:DEEPSEEK1_API_KEY}"
      },
      "models": {
        "deepseek-chat": { "name": "DeepSeek Chat" }
      }
    },
    "deepseek2": {
      "type": "openai-compatible",
      "options": {
        "baseURL": "https://llm.example.com/v1",
        "apiKey": "{env:DEEPSEEK2_API_KEY}"
      },
      "models": {
        "deepseek/deepseek-v4-flash": { "name": "Nested wire id" },
        "flash": { "id": "deepseek/deepseek-v4-flash", "name": "Alias" }
      }
    }
  }
}
```

| Selection | Upstream `model` |
| --- | --- |
| `deepseek1/deepseek-chat` | `deepseek-chat` |
| `deepseek2/deepseek/deepseek-v4-flash` | `deepseek/deepseek-v4-flash` |
| `deepseek2/flash` | `deepseek/deepseek-v4-flash` (via `id`) |

## Install / 安装

**Recommended:**

```bash
brew install --cask yyZe0122/tap/ymz
# or upgrade: brew upgrade --cask ymz
ymz version && ymzd --check
```

```powershell
scoop bucket add ymz https://github.com/yyZe0122/scoop-bucket
scoop install ymz
# or: scoop update ymz
```

**Fallback:**

```powershell
$env:YMZ_VERSION = 'v0.2.3'
irm "https://raw.githubusercontent.com/yyZe0122/YunmengZe-Agent/main/packaging/scripts/install.ps1" | iex
```

```bash
export YMZ_VERSION=v0.2.3
curl -fsSL "https://raw.githubusercontent.com/yyZe0122/YunmengZe-Agent/main/packaging/scripts/install-user.sh" | sh
```

Config root: **`~/.yunmengze`** · `ymz paths user` · `ymz config validate --mode user`.

## Notes / 说明

- Existing installs keep their `agent.json`; only **new** seeds use `deepseek1` / `deepseek2`. Rename providers and env keys when you adopt the new template.
- NewAPI / OpenRouter-style gateways: put the **full upstream model name** (including `/`) as the catalog key or as `models.<key>.id`.
- Affiliate repos: `yyZe0122/homebrew-tap` (`Casks/ymz.rb`), `yyZe0122/scoop-bucket`.
